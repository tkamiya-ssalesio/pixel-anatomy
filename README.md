# 画素の解剖器

情報Ⅰ「情報のデジタル表現」第5回（実教出版『最新情報Ⅰ』第3章 1-4 画像の表現，1-5 画像のデータ量）の授業用シミュレータ．画像を画素のひとつひとつまで拡大して調べ，色のつくり方・画素の数・色の段階・データ量を変えたときの画像の変化を確かめる．

## できること

- **色をつくる**（`#color`）：R・G・B を 0〜255 で決め，各色を16進数（2文字）・10進数・2進数（8ビット，4文字ずつ区切り）で同時に見る．`#RRGGBB` の全体表示と24ビットの2進列，色見本つき．カラーコード（6文字）の直接入力欄は，既定では隠れていて，「カラーコードから調べる（解いたあとで）」にチェックを入れたときだけ出る（入れると R・G・B が変わる．S3 で手で解く前に答えが出ないようにするため）．
  - 答え合わせ欄：「めざすカラーコード」を入れておくと，いまの R・G・B から作った16進数が同じなら「一致」，違えば「まだ違う」と出る．めざす色の見本の四角も出る．直接入力欄から入れた値で一致させたときは「カラーコードから入れた値です」と注記する
  - 光の重なりスイッチ：赤・緑・青の円を重ね，各円の明るさは R・G・B の値に連動する（加法混色．重なりはイエロー・シアン・マゼンタ・白になる）．切るとふつうの重ね描きになる
  - 表示する式：8ビット × 3 ＝ 24ビット，2²⁴ ＝ 16777216 色（256 × 256 × 256），FFFFFF ＝ 白，000000 ＝ 黒．色の例のチップ（赤・緑・青・イエロー・シアン・マゼンタ・白・黒）
- **画素を調べる**（`#pixel`）：見本（鳥・校舎と空・グラデーション・図形）の一部を 20×15 マスに拡大して，画素を1マスずつ見せる．全体の縮小図に表示範囲の枠が出て，押す・なぞる・矢印キー・ボタンで動かせる．マスを押すと，座標（左上が (0, 0)）と RGB（16進・10進）と色見本が出る．格子線は入切できる
- **解像度と階調**（`#resolution`）：同じ画像（見本は 鳥・校舎と空・グラデーション・図形．既定は鳥）を A・B の2枚で並べ，**解像度**（元の 1/1・1/2・1/4・1/8・1/16・1/32）と**階調**（各色 2・4・8・16・256段階．1・2・3・4・8ビット）を別々に動かす．カードごとに横×縦の画素数，1画素のビット数，段階数，データ量（約○KB／MB）を出す．初期状態は A＝1/8・256段階，B＝1/1・4段階（2ビット）
  - 「この粗さで確定」：そのカードの画像を，いま作業中の元画像に置き換える（そのカードのスライダーは最大に戻る）．確定後に解像度・階調を最大にしても粗いまま＝捨てた分はもどらない．「もとの写真にもどす」で初期化する
  - 色のモード（A・B 共通）：カラー／白黒（2値）・グレースケール（後述）．カラーは各色の段階数 n で 1画素 3×log₂n ビット（8段階なら各色3ビット×3＝9ビット）．白黒（2値）・グレースケールは輝度の段階数で決まり，2段階＝白黒画像（2値画像．1ビット），256段階＝グレースケール（8ビット），4・8・16段階＝グレー（2・3・4ビット）と表示する．各段階の下に「1画素あたりの色の数」（2色（2階調），256 × 256 × 256 色 など）も出す
  - 用語は第5回ワークシートにそろえてある：画素（ピクセル），解像度（画素の細かさ），階調（グラデーション），24ビットフルカラー．画面の説明文に出す定義は短くしてある（丸写しはしない）
  - 「数字をかくす」（教員用）：データ量・画素数・ビット数・段階数を隠し，「解像度」「階調」を「区切りの細かさ」「段階の細かさ」に置き換える（段階のボタンは 5つ：いちばん粗い・粗い・ふつう・細かい・いちばん細かい）．タブ名は「画像を粗くする」になり，この画面を開いている間は，リード文の「データ量」とタブ「データ量」も「大きさ」に置き換わる（画面の可視テキストに「データ量」「解像度」「階調」は残らない）．予想の前に使う導入用
- **ラスタとベクタ**（`#zoom`）：同じ図形（円・三角形・斜めの線）を，ラスタ形式（64×64 画素の格子に描いたものを拡大）とベクタ形式（座標と数式から，その倍率で描き直す）で並べて 1・2・4・8・16・32 倍に拡大する．拡大位置は図形の縁の付近が初期値で，なぞる・ボタン・矢印キーで動かせる．ラスタ側は何×何画素か，ベクタ側は図形を表す式（例：`円 中心(32, 32) 半径24 色 #22A391`）を出す．各カードの下に，描くソフトウェア（ラスタ＝ペイント系：ペイント，GIMP，Photoshop など／ベクタ＝ドロー系：Illustrator，Inkscape，PowerPoint の図形 など）と代表的なファイル形式（JPEG（.jpg）・PNG（.png）・GIF（.gif）など／SVG（.svg）など）を短く出す（ワークシートの表と同じ表記．理由を問う文や答えの誘導は置いていない）
- **データ量**（`#data`）：横・縦の画素数（1〜20000）と1画素のビット数（24ビットフルカラー／8ビットのグレースケール（256階調）／1ビットの白黒画像（2階調）．ボタンは3つのまま）から，`ビット数＝横×縦×ビット` → `÷8＝バイト` → `÷1024＝KB` → `÷1024＝MB`（1KB＝1024B，1MB＝1024KB）を順に展開する．あわせて教科書の形（`3×1024×768÷1024÷1024`）と，2のべき乗に分けた約分（`1024＝2¹⁰，768＝3×2⁸ → 3×3×2¹⁸÷2²⁰＝9÷4＝2.25`）を出す．割り切れないときは「≒」で小数第2位まで（さらに小数第1位）．「解像度と階調」のカードのデータ量は，1KB 以上なら「約 ○ KB／MB」（小数第2位まで），1KB 未満で割り切れなければ「約 ○ B」（小数第2位まで）．「縦も横も2倍にする」ボタンと，基準にした値との比（「基準の4倍」）つき．結果だけの欄は作らず，展開を主役にしている

## 授業で使うときのURL

| URL の末尾 | 開く画面 |
|---|---|
| `#color` | 色をつくる |
| `#pixel` | 画素を調べる |
| `#resolution` | 解像度と階調 |
| `#zoom` | ラスタとベクタ |
| `#data` | データ量 |

- `?c=22A391#color`：「めざすカラーコード」を設定して開く．**めざす色の見本の四角だけが出て，R・G・B の値は 0 のまま**（答えが出ない）
- `?hide=1#resolution`：数字をかくした状態で開く（導入用．「区切りの細かさ」「段階の細かさ」の表示）
- `?w=1024&h=768#data`：データ量の画素数を指定して開く（1〜20000）．`?bits=24`（24・8・1）で1画素のビット数も指定できる

### Classroom に載せない注意

答えが出る指定は，生徒に配るURLに入れない．

- **`#data`**：既定が 1024×768・24ビット（設計書 §4.3 のとおり）で開くため，何も付けなくても 2.25MB までの展開が見える．S6 で手計算を終えてから開かせる（先に Classroom に載せない）．`?w=1024&h=768` と `?bits=24` も同じ答えが出る
- **`?c=22A391`（`#color`）**：めざすカラーコードが答えの6文字そのもの．入れると，R・G・B に10進数を入れて照合する活動の「めざす値」が画面に出る．導入（種明かし前）に配らない．教員の画面でだけ使う
- **`#color` のカラーコード直接入力欄**：既定で隠してある．チェックを入れると，スライドの6文字を打つだけで R・G・B と2進が出る．解いたあとの答え合わせで使わせ，導入・解く前は「カラーコードから調べる」にチェックを入れさせない
- **`#pixel` の図形・グラデーション**：マスを押すと RGB が出る．図形の色は教科書の例 `#22A391` を使っていない（答えが拾えないようにした）．鳥の画像にも `#22A391` と同じ色の画素はない（全画素を走査して0件）
- **`#zoom`**：ベクタ側の式とラスタ・ベクタ両方の色に `#22A391` を使っている（設計書には記述がなく，ラスタ・ベクタ側の色として採用した）．導入（種明かし前）に `#zoom` を開かせない
- 導入（予想の前）に配る `#resolution` は，`?hide=1` つきにする

## しくみ

- `index.html` と `img/bird.png` で動く（公開するときは `img/` フォルダごと置く）．外部のライブラリ・フォントは使わない（Canvas だけ）．読む画像は同じフォルダの `img/bird.png` だけで，外部への通信はない．画像はこのブラウザの中だけで処理し，どこにも送信しない
- 見本は4つ．既定は「鳥」で，並びは 鳥・校舎と空・グラデーション・図形．
  - 「鳥」（`img/bird.png`，800×533）：授業者が生成 AI で作成した画像（元は 1536×1024）を，長辺800に縮小して置いた画像ファイル．起動時に読み込み，終わってから画面を描く．`file://` で直接開くと画素の値を取り出せないことがあり，その場合は「校舎と空」に自動で切り替えて「サーバー経由（https／localhost）で開いてください」と出す．授業で手で解読する色コード（#22A391 ＝ R=34，G=163，B=145）と同じ画素は，この画像に1つもない（全画素を走査して確認）
  - 残りの3つは，コードで描く（`Math.random` は使わず，毎回同じ絵になる）．「校舎と空」（800×600．空のなめらかなグラデーション，雲，校舎，木，地面．人・顔は描かない．空のグラデーションは，階調を落としたとき縞が出るようゆるやかに変えている）・「グラデーション」（R・G・B の帯と明るさの帯）・「図形」（輪郭のはっきりした色の図形）．権利の問題がない
- 見本の読み込み中に別の見本や自分の画像を選んだときは，最後に選んだものを使う（古い読み込みの結果は捨てる）
- 自分の画像を読み込める（`<input type="file" accept="image/*">`）．長い辺が800画素になるよう縮小して使う（それより小さい画像は拡大しない）．「画素を調べる」と「解像度と階調」で共通の元画像を使い，切り替えは両画面で同期する
- 縮小は**最近傍**：縮小後の各マスの中心にあたる画素の値をそのまま取り出す（ぼかさない）．拡大表示は，元の大きさに画素のマスのまま引き伸ばす（`imageSmoothingEnabled=false`）．ただし表示する画面の幅より画素の数が多い場合（解像度 1/1・1/2 のとき）は，画面に収めるためだけに，なめらかに縮めて見せている
- 階調は，各色（0〜255）をいちばん近い段階の値に丸める（量子化）．段階は 2・4・8・16・256．8段階の値は 0・36・73・109・146・182・219・255．ディザはかけない
- **色モードの判断**：カラーのときの1画素のビット数＝3×（各色のビット数）．各色2段階のカラーは8色の画像になる．設計書の「1ビット＝白黒」を成り立たせるため，「白黒（2値）・グレースケール」のときは輝度（0.299R＋0.587G＋0.114B）を階調の段階数で丸め，2段階＝白黒画像（2値画像．1ビット/画素），256段階＝グレースケール（8ビット/画素）として示す
- 「確定」した画像は，縮小した画像を元の大きさ（800×600 など）に引き伸ばしたもので，画素の数は同じだが，同じ値のマスが並んでいる．データ量は，確定後の元画像を基準に計算する
- 「ラスタとベクタ」のラスタ側は，64×64 の格子の各画素の中心が図形の内側かどうかで塗り分ける（ぼかさない）．ベクタ側は，同じ式から Canvas の描画命令でその倍率のまま描き直す
- データ量は 1024進．整数だけで割り切れるかを判定して「＝」「≒」を出し分けている
- タッチ・Chromebook でも動くよう pointer イベントで作っている．幅 360px でも横にはみ出さない．`prefers-reduced-motion` のときは動きを止める

## AIが確かめられない項目（博士に確認してほしい）

- 実機の Chromebook での，画像の読み込み（ファイル選択）・`?c=` の入力・タッチ操作（なぞる・押す）
- 空のグラデーションを階調4ビット（16段階）に落としたときの縞の見え方（画面の違いで見え方が変わる）
- 「校舎と空」の見た目（授業の「校舎と空」の写真として問題ないか），「鳥」の見た目（生成 AI の画像として授業で使って問題ないか．縮小後の見え方，拡大したときの画素の見え方）
